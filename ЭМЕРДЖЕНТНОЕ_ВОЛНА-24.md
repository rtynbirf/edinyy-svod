# ЭМЕРДЖЕНТНОЕ ВОЛНЫ-24: мировые практики → выносы дома

**Деятель:** агент Z.ai (третий наблюдатель), такт волны-24, 16.11.2026.
**Мандат Хозяина:** «Иди ищи лучшие мировые тренды практик по своим советам, и выводи только своё эмерджентное. И интегрируй всё у нас».
**Метод:** по каждому фронту — что делает мир (с источниками), затем вынос дома: то, что возникает при наложении мировой практики на канон дома (Конституция 4.2, АГЕНТС, АКТ §5). Вынос — мой, ответственность моя; мир — опора, не пересказ.

## Фронт 1. Ключи и ротация (совет №1)

**Что делает мир.**
- Push protection: секрет не доходит до репо — проталкивание блокируется до попадания в историю ([GitHub Docs: Push protection](https://docs.github.com/en/code-security/concepts/secret-security/push-protection)).
- Fine-grained PAT: токен с точным скоупом per-repo, правами по типам доступа и обязательным сроком жизни вместо вечного классического ключа ([GitHub Docs: Managing your personal access tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)).
- Секрет живёт в зашифрованном хранилище воркфлоу, не в коде, URL и истории; для автоматических пушей — встроенный GITHUB_TOKEN, а не личный ключ ([Community discussion #211475](https://github.com/orgs/community/discussions/211475)).

**Вынос дома (мой).**
1. **«Ключ должен умирать сам, а не по памяти Хозяина».** Мир встраивает смерть секрета в конструкцию (TTL, автоотзыв утечек). Дом пока держит смерть ключа в дисциплине («отзови руками» — журнал 118–119): восемь мёртвых ключей переписки на отзыве — состояние, которого не должно существовать по построению. Эмерджентное правило: **выдача ключа — запись в момент события (п. 115) с паспортом: срок, скоуп, репо, кто отзывает. Ключ, переживший свой такт, мёртв по правилу — отзыв происходит по записи, а не по памяти.**
2. **«Чат — курьер, не хранилище».** Дом уже прав по механике (значение живёт в tmp/600, п. 116), но произнесение в переписке оставляет труп значения в истории чата навсегда. Форма следующей волны: fine-grained ключ с TTL ≤ 7 дней и скоупом на один репо; чат несёт факт выдачи, значение — tmp/600. Исполнение — руки Хозяина в настройках GitHub; дом фиксирует форму.
3. **«Аксиома 4 как барьер в коде».** Мир делает блокировку платформенно (push protection) — дом делает её независимо от платформы: CI-сторож, введённый этим ходом, держит барьер секретов на диффе каждого хода.

## Фронт 2. Тампер-эвиденс: пломба как код (совет №2)

**Что делает мир.**
- SLSA — чек-лист стандартов и контролей против вмешательства (tampering) и за целостность артефактов ([slsa.dev](https://slsa.dev)).
- SLSA provenance — проверяемая информация, ведущая артефакт назад по всем звеньям цепочки ([slsa.dev/provenance](https://slsa.dev/provenance)).

**Вынос дома (мой).**
1. Дом уже стоит на шкале SLSA, не зная того: SHA-манифесты пачек (волна-22: 15 файлов; волна-23: 10+1) — это provenance-манифесты литературного канона. Эмерджентная шкала пломб дома: **П-0 манифест (есть) → П-1 внешняя обязательная проверка (введено этим ходом) → П-2 подписанное происхождение (свидетельство Ed25519 волны-22, уровень V3 — уже есть) → П-3 required check + protected branch (руки Хозяина в настройках репо).**
2. **«Автопилот не может тронуть канон незаметно».** РЕВО перековывает паспорта поверх волн (зафиксировано в тактах волн-22 и 23). Сторож с append-only контролем журнала делает любое касание канона видимым фактом: это гарантия неизменяемого журнала (WORM) мира, выращенная на git-диффе дома.
3. Свидетельство волны-22 — дом уже имеет прото-provenance П-2: подпись третьей стороны над корпусом 492 байта. Следующая пачка может описывать происхождение в форме SLSA (subject + builder + source + commit), но каноном дома — «свидетельство».

## Фронт 3. Индекс и память дома (советы №3 и №4)

**Что делает мир.**
- ADR — документ, фиксирующий значимое архитектурное решение вместе с контекстом и последствиями ([architecture-decision-record](https://github.com/architecture-decision-record/architecture-decision-record), [adr.github.io](https://adr.github.io)).
- Решения живут в репозитории рядом с кодом (docs-as-code) и ведутся единым реестром ([Google Cloud: ADR overview](https://docs.cloud.google.com/architecture/architecture-decision-records)).

**Вынос дома (мой).**
1. Журнал дома (п. 115) и ЛЕТОПИСЬ района — это и есть ADR дома: запись несёт время, вынесшего и основание, то есть контекст и основание решения. Чего не было — единого реестра, из которого каждый ход достижим. Введено этим ходом: **INDEX_ДОМА.md — волна → деятель → репо/артефакт → коммит → записи. Правило усиливается: ход без индексной строки для дома не достижим — по духу п. 115 не существует.**
2. **«Свод — канон, район — пачка».** Дрейф свода (последний содержательный коммит — волна-16 при живых волнах 17–23) снят границей, зафиксированной журналом 124: свод несёт канон, Конституцию, журнал и память; районы несут пачки, доказательства и свидетельства. Это домашняя версия разделения мирового docs-as-code.
3. Эмерджентная проверка волны-25: сверка ссылочной целостности — каждая новая запись журнала имеет индексную строку, каждая индексная строка имеет живой SHA на удале (ls-remote).

## Фронт 4. Прогоны и доказательность (совет №5)

**Что делает мир.**
- Reproducible builds: независимо проверяемый путь от исходника к артефакту — тот же источник, среда и инструкция дают тот же результат ([reproducible-builds.org](https://reproducible-builds.org)).
- Воспроизводимость сборок валидируется регулярным процессом, а не намерением (AWS Well-Architected, [DL.CI.7](https://docs.aws.amazon.com/wellarchitected/latest/devops-guidance/dl.ci.7-validate-the-reproducibility-of-builds.html)).

**Вынос дома (мой).**
1. Глава V дома («разрушаемая догадка, поддерживаемая прогонами») — это reproducible builds для утверждений. Эмерджентное правило: **цифра в документе без ссылки на артефакт прогона — не-факт.** Цифра Полимата «энтропия среды 0.969→0.010 под непрерывным стрессом» (волна-23) — разрушаемая догадка до протокола прогона: код v3 читается, запускается в песочнице, протокол с SHA-артефактом вписывается в пачку. Волна-25.
2. Прогон делается повторяемым по форме мира: фиксированная среда, фиксированный вход, SHA фиксированного выхода — проверяющий агент воспроизводит двумя командами, как уже сделано со свидетельством волны-22 (verify_witness.py).

## Фронт 5. Дрели восстановления (совет №6)

**Что делает мир.**
- Game day — симулированная DR-дрель, испытывающая людей и процедуры не в момент бедствия ([Ad Hoc: guide to building a game day](https://adhoc.team/2023/01/31/engineering-chaos-a-guide-to-building-a-game-day)).
- Учения идут по каденции: от настольных до chaos-инженерии ([Firefly: resilience testing](https://www.firefly.ai/academy/resilience-testing-in-cloud)).
- Тестирование восстановления не менее важно, чем сам бэкап; стратегия backup and restore — базовая из четырёх DR-стратегий ([EON: AWS DR](https://www.eon.io/blog/aws-disaster-recovery-plan)).

**Вынос дома (мой).**
1. **«Песочница смертна — дом нет».** FSM-скрипт уже умирал в /tmp между тактами; память агента не переживает переработку песочницы. Эмерджентный ритуал: **ДРЕЛЬ ВОССТАНОВЛЕНИЯ — такт, открывающийся не ВХОДОМ, а ВОССТАНОВЛЕНИЕМ: дом собирается из удала (клоны, FSM, сверка пломб и индекса) и только затем делает дело. Запись дрели несёт RTO дома — время от нуля до первого действия.**
2. **«Непроверенная память — нет памяти».** Дом доверяет только удалу и пломбам. Индекс (фронт 3) делает дрель машинной: восстановление сверяется с INDEX_ДОМА.md строка за строкой.
